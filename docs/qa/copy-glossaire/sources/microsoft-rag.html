Génération augmentée par récupération (RAG) dans Recherche Azure AI

Dans cet article

Note

Recherche Azure AI est disponible via le portail Azure, les API REST et les SDK Azure. Il sous-tend également Foundry IQ, la couche de connaissances managée qui transforme le contenu d’entreprise en bases de connaissances réutilisables et prenant en charge les autorisations pour les agents dans le portail Microsoft Foundry.

La génération augmentée par récupération (RAG) est un modèle qui étend les capacités des LLM en ancrant les réponses dans votre contenu propriétaire. Bien que conceptuellement simples, les implémentations RAG font face à des défis importants.

Les défis de RAG

Défi Descriptif
Compréhension des requêtes Les utilisateurs modernes posent des questions complexes, conversationnelles ou vagues avec un contexte supposé. La recherche par mot clé classique échoue lorsque les requêtes ne correspondent pas à la terminologie du document. Pour RAG, un système de récupération d’informations doit comprendre l’intention, pas seulement correspondre aux mots.
Accès aux données à plusieurs sources Le contenu d'entreprise s'étend sur des plateformes comme SharePoint, les bases de données, Blob Storage et d'autres systèmes. La création d’un corpus de recherche unifié sans perturber les opérations de données est essentielle.
Contraintes de jeton Les LLM acceptent des entrées de tokens limitées. Votre système de récupération doit retourner des résultats très pertinents et concis, non des amas de documents exhaustifs.
Attentes en matière de temps de réponse Les utilisateurs attendent des réponses basées sur l’IA en secondes, et non en minutes. Le système de récupération doit équilibrer l'exhaustivité avec la vitesse.
sécurité et gouvernance L’ouverture de contenu privé aux machines virtuelles LLM nécessite un contrôle d’accès granulaire. Les utilisateurs et les agents doivent uniquement récupérer du contenu autorisé.

Comment Recherche Azure AI répond aux défis DE RAG

Recherche Azure AI fournit deux approches conçues spécifiquement pour ces défis RAG :

  • Recherche agentique : un pipeline RAG complet avec planification des requêtes basée sur des LLM (aperçu), accès multi-source et réponses structurées optimisées pour une utilisation par des agents.

  • Modèle RAG classique : l’approche éprouvée à l’aide de la recherche hybride et du classement sémantique, idéale pour des exigences plus simples ou lorsque des fonctionnalités en disponibilité générale sont requises.

Les sections suivantes expliquent comment chaque approche résout des défis RAG spécifiques.

Résolution des problèmes de compréhension des requêtes

Le problème : Les utilisateurs demandent « Quelle est notre politique d’PTO pour les travailleurs à distance embauchés après 2023 », mais les documents disent « congés », « telecommute » et « embauches récentes ».

Solution de récupération agentique :

  • LLM analyse la question et génère plusieurs sous-requêtes ciblées.
  • Décompose les questions complexes en recherches ciblées.
  • Utilise l’historique des conversations pour comprendre le contexte.
  • Exécution parallèle entre les sources de connaissances.

Solution RAG classique :

  • Les requêtes hybrides combinent la recherche de mots clés et de vecteurs pour un meilleur rappel.
  • Les résultats du classement sémantique sont réévalués d'après la signification, et non seulement sur des mots clés.
  • La recherche de similarité vectorielle correspond aux concepts, pas aux termes exacts.

En savoir plus sur la planification des requêtes (version préliminaire).

Résolution des défis liés aux données multisources

Le problème : Stratégies RH dans SharePoint, avantages dans les bases de données, actualités de l’entreprise sur les pages web : la création de copies interrompt les opérations de gouvernance et de routine des données.

Solution de récupération agentique :

  • Les bases de connaissances unifient plusieurs sources de connaissances.
  • Requête directe sur SharePoint distant et Bing (aucune indexation nécessaire) pour compléter le contenu de l’index.
  • Les instructions de récupération guident le LLM vers les sources de données appropriées.
  • Génération automatique de pipeline d’indexation pour Azure Blob, OneLake, ainsi que les contenus ingérés depuis SharePoint ou d'autres sources externes.
  • Interface de requête unique et plan de requête sur toutes les sources.

Solution RAG classique :

  • Les indexeurs extrayent plus de 10 sources de données Azure.
  • Pipeline de compétences pour la segmentation, la vectorisation, la verbalisation d’image et l’analyse.
  • L’indexation incrémentielle maintient le contenu actualisé.
  • Vous contrôlez ce qui est indexé et comment.

En savoir plus sur les sources de connaissances..

Résolution des défis liés aux contraintes de token

Le problème : GPT-4 accepte environ 128 000 jetons, mais vous avez 10 000 pages de documentation. Tout envoyer gaspille des tokens et dégrade la qualité.

Solution de récupération agentique :

  • Retourne une réponse structurée avec uniquement les blocs les plus pertinents
  • Le suivi des citations intégré affiche la provenance
  • Le journal d’activité des requêtes explique ce qui a été recherché
  • La synthèse des réponses facultatives réduit davantage l’utilisation des jetons

Solution RAG classique :

  • Le classement sémantique identifie les 50 premiers résultats les plus pertinents
  • Limites de résultats configurables (top-k pour les vecteurs, top-n pour le texte) et seuils minimaux
  • Les profils de scoring améliorent le contenu critique
  • Les instructions SELECT déterminent quels champs sont renvoyés.

En savoir plus sur le réglage de pertinence.

Résolution des défis liés au temps de réponse

Le problème : Les utilisateurs attendent des réponses en 3 à 5 secondes, mais vous interrogez plusieurs sources avec un traitement complexe.

Solution de récupération agentique :

  • Exécution de sous-requête parallèle (non séquentiel)
  • Effort de raisonnement réglable (minimal/faible/moyen)
  • Classement sémantique prédéfini (aucune orchestration supplémentaire)

Solution RAG classique :

  • Temps de réponse de requête en millisecondes
  • Les requêtes uniques réduisent la complexité
  • Vous contrôlez le délai d’expiration et la logique de nouvelle tentative
  • Architecture plus simple avec moins de points d’échec

Résolution des problèmes de sécurité

Le problème : Les données financières ne doivent être accessibles qu’à l’équipe financière, même lorsqu’un cadre demande au chatbot.

Solution de récupération agentique :

  • Contrôle d’accès au niveau de la source de connaissances
  • Hérite des autorisations SharePoint pour les requêtes effectuées sur SharePoint distant
  • Hérite des métadonnées de permissions Microsoft Entra ID pour le contenu indexé depuis stockage Azure
  • Sécurité basée sur les filtres au moment de la requête pour d’autres sources de données
  • Isolation réseau via des points de terminaison privés

Solution RAG classique :

  • Filtrage de sécurité au niveau du document
  • Hérite des métadonnées de permissions Microsoft Entra ID pour le contenu indexé depuis stockage Azure
  • Sécurité basée sur les filtres au moment de la requête pour d’autres sources de données
  • Isolation réseau via des points de terminaison privés

En savoir plus sur la sécurité.

RAG moderne avec récupération par agentivité

Recherche Azure AI est une solution éprouvée pour les charges de travail RAG. Il fournit désormais la récupération agentique, un pipeline spécialisé conçu spécifiquement pour les modèles RAG. Cette approche utilise des machines virtuelles LL pour décomposer intelligemment les requêtes utilisateur complexes en sous-requêtes ciblées, les exécute en parallèle et retourne des réponses structurées optimisées pour les modèles d’achèvement de conversation.

La récupération agentique représente l’évolution des schémas RAG monorequête traditionnels vers la récupération intelligente multirequêtes, fournissant :

  • Planification des requêtes prenant en compte le contexte à l’aide de l’historique des conversations
  • Exécution parallèle de plusieurs sous-requêtes prioritaires
  • Réponses structurées avec des données de base, des citations et des métadonnées d’exécution
  • Classement sémantique intégré pour une pertinence optimale
  • Synthèse de réponses facultative qui utilise une réponse formulée par LLM dans la réponse de requête

Vous avez besoin de nouveaux objets pour ce pipeline : une ou plusieurs sources de connaissances (chacune pointe vers du contenu pouvant faire l’objet d’une recherche, comme un index de recherche ou un site de SharePoint distant), une base de connaissances (l’objet interrogeable qui unifie ces sources) et l’action de récupération que vous appelez à partir du code de l’application, telle qu’un outil qui fonctionne avec votre agent IA.

Pour les nouvelles implémentations RAG, commencez par la récupération agentique. Pour les solutions existantes, envisagez de migrer pour tirer parti d’une meilleure précision et de la compréhension du contexte.

Modèle RAG classique pour Recherche d’IA Azure

Classic RAG utilise l’architecture d’exécution de requête d’origine où votre application envoie une requête unique à Recherche Azure AI et orchestre le transfert vers un LLM séparément. Votre LLM déployé formule une réponse à l’aide du jeu de résultats aplati issu de la requête. Cette approche est plus simple avec moins de composants, et plus rapidement, car il n’y a pas d’implication LLM dans la planification des requêtes.

Pour plus d’informations sur l’implémentation de RAG classique, consultez le référentiel azure-search-classic-rag.

Préparation du contenu pour RAG

La qualité RAG dépend de la façon dont vous préparez le contenu pour la récupération. La Recherche Azure IA prend en charge :

Défi de contenu Comment Recherche Azure AI aide
Documents volumineux Segmentation automatique (intégrée ou via des compétences)
Langues multiples Plus de 50 analyseurs linguistiques pour le texte, les vecteurs multilingues
Images et fichiers PDF OCR, analyse d’image, verbalisation d’image, compétences d’extraction de documents
Besoin de recherche de similarité Vectorisation intégrée (Azure OpenAI, Azure Vision dans Foundry Tools, personnalisée)
Incompatibilités de terminologie Mappages de synonymes, classement sémantique

Pour la récupération agentique : Utilisez des sources de connaissances qui génèrent automatiquement des pipelines de segmentation et de vectorisation.

Pour RAG classique : Utilisez des indexeurs et des ensembles de compétences pour créer des pipelines personnalisés ou pousser du contenu prétraité via l'API push.

Optimiser la pertinence et le rappel

Comment fournissez-vous les meilleures données de base pour la formulation de réponses LLM ? Il s’agit d’une combinaison de contenu approprié, de requêtes intelligentes et de logique de requête qui peut identifier les meilleurs blocs pour répondre à une question.

Lors de l’indexation, utilisez la segmentation pour subdiviser des documents volumineux afin que les parties puissent être mises en correspondance indépendamment. Incluez une étape de vectorisation pour créer des incorporations utilisées pour les requêtes vectorielles.

Côté requête, pour garantir les résultats les plus pertinents pour votre implémentation RAG :

  • Utilisez des requêtes hybrides qui combinent le mot clé (non-vecteur) et la recherche vectorielle pour un rappel maximal. Dans une requête hybride, si vous doublez sur la même entrée, une chaîne de texte et son équivalent vectoriel génèrent des requêtes parallèles pour les mots clés et la recherche de similarité, retournant les correspondances les plus pertinentes de chaque type de requête dans un jeu de résultats unifié.

  • Utilisez le classement sémantique, intégré à la récupération agentique, facultatif pour le RAG classique.

  • Appliquez des profils de scoring pour améliorer des champs ou des critères spécifiques.

  • Affinez avec des paramètres de requête vectorielle pour la pondération vectorielle et les seuils minimums.

Pour plus d’informations, consultez recherche hybride et classement sémantique.

Choisir entre la récupération agentique et le RAG classique

Utilisez la récupération agentique quand :

  • Votre client est un agent ou un chatbot.
  • Vous avez besoin de la pertinence et de la précision les plus élevées possibles.
  • Vos requêtes sont complexes ou conversationnelles.
  • Vous souhaitez des réponses structurées avec des citations et des détails de requête.
  • Vous créez de nouvelles implémentations RAG.

Utilisez le RAG classique quand :

  • Vous avez besoin de fonctionnalités en disponibilité générale uniquement.
  • La simplicité et la vitesse sont des priorités par rapport à la pertinence avancée.
  • Vous disposez d’un code d’orchestration existant que vous souhaitez conserver.
  • Vous avez besoin d’un contrôle précis sur le pipeline de requête.

Une solution RAG qui inclut des agents et Recherche Azure AI peut tirer parti de Foundry IQ, en tant que point de terminaison unique d’un agent vers une couche de connaissances qui fournit des données de base. Foundry IQ utilise la récupération agentique.
